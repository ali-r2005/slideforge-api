# Table Row Source Architecture

This document explains the schema-driven approach to table row generation in SlideForge.

## Overview

Tables in SlideForge now support multiple **row generation strategies** defined declaratively in the schema via the `row_source` field. This replaces the previous hardcoded date-range-only approach.

## Row Source Types

### 1. Date Range (`type: "date_range"`)

Generates one row per day between a start and end date.

**Schema Definition:**
```json
{
  "name": "program_schedule",
  "type": "table",
  "label": "Program Schedule",
  "row_source": {
    "type": "date_range",
    "config": {
      "start_field": "event_start_date",
      "end_field": "event_end_date"
    }
  },
  "columns": ["Matinée", "Midi", "Après-midi", "Soir"]
}
```

**Frontend Behavior:**
- Frontend receives `event_start_date` and `event_end_date` from form
- Frontend calculates number of days between dates
- Frontend generates one row per day with `date` key: `"2025-06-01"`
- User fills cells for each day
- Frontend sends complete rows array to backend

**Form Data Structure:**
```json
{
  "event_start_date": "2025-06-01",
  "event_end_date": "2025-06-03",
  "program_schedule": [
    { "date": "2025-06-01", "Matinée": {...}, "Midi": {...}, ... },
    { "date": "2025-06-02", "Matinée": {...}, "Midi": {...}, ... },
    { "date": "2025-06-03", "Matinée": {...}, "Midi": {...}, ... }
  ]
}
```

### 2. User Provided (`type: "user_provided"`)

Users explicitly add/remove rows as needed. No automatic row generation.

**Schema Definition:**
```json
{
  "name": "team_members",
  "type": "table",
  "label": "Team Members",
  "row_source": {
    "type": "user_provided"
  },
  "columns": ["Name", "Email", "Role"]
}
```

**Frontend Behavior:**
- Show `+ Add Row` button
- User clicks to add as many rows as needed
- User can delete rows
- No date column needed
- User fills in each row's cells

**Form Data Structure:**
```json
{
  "team_members": [
    { "Name": "John Doe", "Email": "john@...", "Role": "Manager" },
    { "Name": "Jane Smith", "Email": "jane@...", "Role": "Developer" }
  ]
}
```

### 3. Fixed (`type: "fixed"`)

Generates a fixed number of empty rows.

**Schema Definition:**
```json
{
  "name": "department_summary",
  "type": "table",
  "label": "Department Summary",
  "row_source": {
    "type": "fixed",
    "config": {
      "count": 5
    }
  },
  "columns": ["Department", "Budget", "Status"]
}
```

**Frontend Behavior:**
- Show exactly 5 empty rows
- No add/delete buttons needed
- User fills in the pre-defined rows

**Form Data Structure:**
```json
{
  "department_summary": [
    { "Department": "Engineering", "Budget": "500K", "Status": "On Track" },
    { "Department": "Marketing", "Budget": "250K", "Status": "On Track" },
    ...
  ]
}
```

## Backend Processing

### Schema Validation

The backend validates `row_source` configuration:
- **date_range**: Must have `config.start_field` and `config.end_field` pointing to date fields
- **fixed**: Must have `config.count` as positive integer
- **user_provided**: No config required

### Form Data Validation

The schema validator (`schema_validator.py`) checks:
- Table data is an array of objects
- Each row contains all required columns
- For `date_range` rows: must include valid ISO `date` field
- For `user_provided` and `fixed` rows: `date` field is optional

### Table Filling

The `fill_table()` function in `table_service.py`:
- Takes rows from form_data (already generated by frontend)
- Fills PowerPoint table with the provided rows
- Handles cell_structure (parts like context, team_building, etc.)
- Works identically regardless of row_source type

## Migration from Old Format

**Old Format (deprecated):**
```json
{
  "type": "table",
  "date_range_start_field": "event_start_date",
  "date_range_end_field": "event_end_date"
}
```

**New Format (required):**
```json
{
  "type": "table",
  "row_source": {
    "type": "date_range",
    "config": {
      "start_field": "event_start_date",
      "end_field": "event_end_date"
    }
  }
}
```

## Adding New Row Source Types

To add a new row source type:

1. **Update schema_loader.py:** Add validation for the new type
2. **Update schema_validator.py:** Add validation rules for form data
3. **Update frontend:** Render UI based on `row_source.type`
4. **Update table_service.py:** If special processing is needed

## Files Modified

- `templates/template7.json` — Updated to use new `row_source` format
- `app/utils/schema_loader.py` — Validates `row_source` configurations
- `app/utils/schema_validator.py` — Validates form data based on row_source type
- `app/services/table_service.py` — Fills table with provided rows (no changes needed)
